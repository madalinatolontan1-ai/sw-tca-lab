HW TCA lab: production test coverage analysis

Lab guide · Testing, 4th year · Faculty of Electronics, Telecommunications and Information Technologies, UPT

1. Objectives

By the end of the lab you will be able to:

  • explain what production test coverage means and why a passed test does not prove the board is defect-free;
  • rate severity (S), occurrence (O) and detection (D) for the failure modes of a board, using the AIAG-VDA scales;
  • compare the AOI, AXI, ICT and FT test methods for a given defect and justify the detection chosen for the functional test;
  • propose testability improvements (test points, extra inspection, new tests) and document the residual risk.

2. Background

2.1 Test coverage analysis (HW TCA)

After assembly, a circuit board goes through several test stages: automated optical inspection (AOI), X-ray inspection (AXI), in-circuit test (ICT) and functional test (FT). Each stage sees different defect types. Test coverage analysis answers the question: if the board has a given manufacturing defect, does any test catch it before it reaches the customer, and how reliably?

A passed test only says that the measured properties are fine. If ICT measures a resistor, we know it is present, has the right value and is neither open nor shorted; we know nothing about the components we did not measure [1]. That is why the analysis does not count tests; it takes every possible failure mode and gives it a detection value for each method.

2.3 S, O, D and action priority (AP)

The risk of each failure mode is described by three ratings from 1 to 10, following the AIAG-VDA FMEA handbook [3]:

  • S, severity, is rated on the effect: how serious the effect is for the customer. In the lab, S follows from the effect class E1–E9 (appendix A).
  • O, occurrence, is rated on the cause: how likely the defect is, given the prevention (appendix B).
  • D, detection: how reliably we catch the defect before the board ships. 1 means almost certainly, 10 means we cannot detect it.

All tests run on every board, so the combined detection is the minimum of the methods' D values: D = min(D AOI, D AXI, D ICT, D FT). S, O and D give the action priority AP (H, M or L) from the AIAG-VDA table (appendix C). We do not use RPN = S × O × D: the same RPN can hide very different risks [4].

2.4 Residual risk

Risk assessment means identification, analysis and evaluation [5]. Where AP is H or M, we first look for an improvement. What remains after the improvements is the residual risk: it must be documented, with the reason it remains and the decision taken (accepted or action proposed).

5. Procedure

Each variant has 12 failure modes. For each mode, fill in its row of the analysis sheet following the steps below.

Step 1. Severity (S)

Read the effect and choose the effect class (E1–E9, appendix A). S follows automatically from the class. Effects that only reduce EMC filtering get E9 (regulatory non-compliance, UNECE R10), even if the function is not affected.

Step 2. Occurrence (O)

Choose O from the AIAG-VDA scale (appendix B). For a mature SMT technology with a stable process the value is usually low. Use the same reasoning for all modes and justify it in your conclusion.

Step 3. Detection at AOI, AXI and ICT

The app calculates D for AOI, AXI and ICT from the detection rules (appendix E) and shows the reason under the value. Two additional rules:

  • C5: for the THT connectors (J1, J2, JP1), solder defects (pin open, pin short, open) are on the BOTTOM side, which AOI does not inspect at first, so AOI = 10. If you enable AOI on BOTTOM, it becomes 1.
  • C7: marked parts (R1–R5, U1) have their value printed on the package, so AOI can partly catch a wrong value (D = 5).
  • ICT uses the “with TP” value only if all nets of the part have a test point; otherwise the “without TP” value applies.

Step 4. Detection at the functional test (FT)

You decide the FT detection yourselves, based on the FT1–FT8 test list (appendix D). For each mode:

  1. read the effect and the defect type (missing, open, short, wrong value, wrong polarity, wrong functionality);
  2. look in the “What it can catch” column for a test that matches the part and the defect type;
  3. check the schematic: which net the part is on, which signal the test measures and which connector pin it reaches;
  4. choose the most suitable test, or NONE if none fits (NONE means D FT = 10);
  5. choose D FT and write why. As a guide: 1, the test surely catches the defect; 5, it catches it only partly (for some values, under some conditions or intermittently); 10, no test catches it.

The justification is mandatory and is graded: a value without an explanation earns no points.

Figure 3. The functional test list in the app.

Step 5. Action priority (AP)

The app calculates D = the minimum of the four methods and AP from the AIAG-VDA table. The “AP no impr.” column keeps the initial result so you can compare.

Step 6. Improvements

For the modes with AP H or M, propose improvements and watch how D and AP change:

  • test points: tick the nets you add a test point to (VREF is not connected and cannot get a TP);
  • AOI on BOTTOM: inspection of the THT solder joints;
  • new FT tests: describe the test (what you measure, where, which limit), add it, then choose it in the “New FT test (impr.)” column for the modes it catches, with its D value.

Every improvement has a cost: a test point takes board space and a fixture pin, a new test adds test time. Propose only what reduces a risk.

Step 7. Residual risk

Where AP stays H or M after the improvements, fill in the “Residual risk assessment” column: choose risk accepted or action proposed and write why the risk remains, what else could be done or why you accept it.

Step 8. The report

In the Report tab, write your improvement proposals and conclusion, check the generated sheet, then click Send report. The report goes straight to your instructor. You can send it again; the last submission counts. If the submission is not confirmed, download the report (.html) and keep it.

Three modes explained

R2 missing. Effect: the RC filter on CANL is disconnected, EMC filtering is reduced, the function is not affected. Class E9, S = 9. AOI sees the missing part: D = 1. No FT test measures the RC filter, so FT = NONE (D FT = 10). D = min(1, 3, 5, 10) = 1, AP = L. The example shows why combining methods matters: FT does not see the defect at all, but AOI surely catches it.

J2 pin 2 CAN_L open. The joint is on the BOTTOM side, so AOI = 10 (C5). AXI = 3. ICT = 10, because there is no test point on CANL. The matching test is FT7, CAN transmission through the connectors. Justification for D FT = 5: with CAN_L open, communication may still work over a short distance, so FT7 catches the defect only sometimes. D = min(10, 3, 10, 5) = 3, AP = L. After enabling AOI on BOTTOM, AOI = 1 and D = 1.

R5 wrong value. R5 is marked, so AOI = 5 (C7). AXI = 10, it cannot see the value. ICT = 5 without test points. FT2 only checks that the LED is on, not its brightness, so FT = NONE. D = 5, AP = L. With test points on N_LED and GND, ICT measures the value of R5 (D ICT = 1), and D becomes 1.

7. What is assessed

  • the correct effect class and occurrence for all modes;
  • the choice of FT test and D FT value, with justification;
  • the proposed improvements and their effect on AP;
  • the residual risk documentation for the modes that stay H or M;
  • the conclusion in the report.

8. Review questions

  1. Why is the combined detection the minimum of the D values, and what assumption does this rule make?
  2. Why does a high percentage of accessible nodes at ICT not automatically mean good coverage?
  3. Why can two modes with the same RPN have different action priorities?
  4. Which defects of the CAN module can the functional test not catch, and why?
  5. On which nets should test points be added so that ICT can measure the RC filters on CANH and CANL?
  6. When is a residual risk acceptable, and who decides?
